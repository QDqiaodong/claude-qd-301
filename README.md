# 建筑工地 · 料具堆场与安全巡检

工地的日常台账：**堆场分区**、**材料台账**、**浇筑预扣**、**进出场流水**、**安全巡检**。

这张仓的业务重心在「进出场流水」—— 材料的结存不是手填的，而是进场加、出场减，
一笔一笔流水累出来的；出场时可用余量不够会被拦住。想调整数量只能补反向流水，改不了历史。

「浇筑预扣」是浇筑段开盘前的占料动作：只占可用余量、不动账面结存、不提前写出场流水；
开盘兑现时才补一笔等量出场流水，取消或泵车故障就作废、余量当场还回。
台账上「账面结存」和「可用余量」（结存 − 占用中预扣）是两列，能再预扣、能出场的都看余量。

## 技术栈

- 后端：Spring Boot 3.3 / Java 17、Spring Data JPA、MySQL 8、Redis 7
- 前端：Vue 3（Options API）+ Element Plus + Vite，nginx 反代
- 一键起：`./start.sh`（内部就是 `docker compose up -d --build`）

## 业务模块

1. **堆场分区**（`yard`）—— 堆场编号与名称、占地/可堆量、可用与停用（停用前要求清空材料）
2. **材料台账**（`material`）—— 材料编号、类别、归属堆场、账面结存（只读，由流水推出来）与可用余量（结存 − 占用中预扣）
3. **浇筑预扣**（`pour_reservation`）—— 选堆场和材料、定预扣数量和计划开盘日；占用中 → 已兑现（补等量出场流水）/ 已作废（余量还回），只走一次；堆场停用或挂着待整改不合格巡检时不许新开、不许改大
4. **进出场流水**（`material_movement`）—— 进场 / 出场登记，自动加减结存；出场按可用余量拦截，出入库留痕
5. **安全巡检**（`safety_inspection`）—— 打分、判定合格与否、不合格整改到闭环
